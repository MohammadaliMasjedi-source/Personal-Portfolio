# Ten-minute interview demonstration

This is a rehearsal plan. It does not claim that the candidate has already delivered online customer training.

| Time | What to demonstrate | What to ask |
|---|---|---|
| 0:00–1:00 | State the fictional customer question and the three learning goals | “Have you used an API before, or should I start with the browser?” |
| 1:00–3:00 | Show the app and trace one search request in Network | “Which part changed when I searched?” |
| 3:00–5:00 | Create an enrolment, read the 201 response, repeat it to get 409 | “Would retrying the same request solve this?” |
| 5:00–7:30 | Compare the left-join report with COUNT(*) on an empty workshop | “Should this workshop appear with zero or disappear?” |
| 7:30–9:00 | Explain parameterised SQL and the purpose of a small Git diff | “What would you check before sharing this change?” |
| 9:00–10:00 | Invite the learner to explain one layer; recap a next practice step | “Can you explain the API's role in your own words?” |

Prepare before applying/interviewing:

1. Run the full lab yourself and change one query without the answer key.
2. Explain the difference between your earlier SOAP integration work and this newly prepared REST example. Do not describe SOAP experience as prior REST delivery.
3. Practise the demonstration aloud in English. If making a video, record only the fictional lab and your own narration.
4. Prepare one real teaching story and one real software-user support story: audience, difficulty, what you did, and the outcome you can actually substantiate. No invented learner numbers or measured improvement.
5. Be candid about which tools you have used professionally and which you are demonstrating through this sample. This exercise is not a substitute for previous virtual instructor-led training experience.
